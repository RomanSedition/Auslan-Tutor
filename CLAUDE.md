# Auslan Tutor

A static lesson wiki for learning Auslan. The author asks for lessons; Claude writes them
as HTML pages that embed Auslan Signbank videos. No build step and no dependencies.

Personal notes about the author (learning progress, preferences) go in `CLAUDE.local.md`. It's
gitignored, so read it if it exists, and never copy its contents into committed files.

**The site is public** (https://auslan-tutor.com.au/, served by GitHub Pages with a custom domain; the old github.io URL redirects), and other people use it.
Each visitor's progress, name and state live in their own browser's localStorage.
- Never put personal details in pages or committed files. For the learner's name use
  `<span class="user-name"></span>` (or `data-format="spelled"` for the S-A-M style), and use `fs:@name`
  and `{name}` in `<sign-phrase>`.
- Anything only the author needs (like the "ask Claude for a lesson" box) gets `class="author-only" hidden`.
  These elements are shown only on localhost.
- Once a lesson passes `tools/check.py`, commit and push to `main` so it goes live (Pages redeploys in about a minute).
  If `git push` has no credentials, use `git -c credential.helper='!gh auth git-credential' push`.

Run it locally: `./serve.sh` (or the `auslan-tutor` alias) → http://localhost:8000. It has to be localhost,
not file://, because the camera and `fetch()` need it.

## Layout
- `index.html`, `glossary.html`, `review.html`: pages that read `data/*.json`
- `lessons/NNN-slug.html`: one page per lesson. `lessons/_template.html` is the canonical skeleton.
- `data/lessons.json`: ordered lesson list `{id, slug, title, date, summary, signs[]}`
- `data/signs.json`: every sign taught, keyed by a kebab-case gloss key (`hello`, `thank-you`, `letter-a`):
  `{label, english, hint, category: "vocab"|"fingerspelling", video, poster, entry, region, lessons[], variants?}`
  - `variants` (optional): `[{region, video, poster, entry}]`, one per regional Signbank entry. When the page loads,
    `app.js` copies the variant that best fits the visitor's state onto the sign (exact state, then dialect,
    then Australia-wide). Cards show chips to switch between versions. The top-level fields are a fallback.
- `data/spelling-words.json`: word bank for the fingerspelling game
- `data/phrases.json`: every `<sign-phrase>` from the lessons, generated by `tools/phrases.py` (don't edit by hand)
- `assets/app.js`: custom elements `<auslan-sign>`, `<auslan-quiz>`, `<sign-phrase>`, `<fingerspell-drill>`,
  plus the mirror panel, record & compare, header and footer, lesson nav, region handling and progress (localStorage)
- `curriculum.md`: the roadmap. Tick items off as lessons are written.
- `PLANNED_FEATURES.md`: app features that were discussed but not built yet. When one gets built, move it to "Done".
- `tools/signbank.py`: look up signs on Signbank (JSON out, cached in `tools/.cache/`)
- `tools/framesheet.swift`: renders a sign video as a frame contact sheet so you can see how it's made
- `tools/trim.py` + `tools/motion.swift`: detect the signing window (`trim`) and letter holds (`hold`) in each clip
- `tools/check.py`: validates lessons and data (`--online` also checks every video URL, including variants)

## Delivering a lesson ("next lesson", "a lesson on X")
1. **Plan.** Read `curriculum.md`, `CLAUDE.local.md` (if present), `data/lessons.json` and the keys in
   `data/signs.json`. Pick the topic: the next unticked item, or what was asked for. Aim for 10–16 new signs.
   Reuse 3–5 known signs in phrases and quiz options.
2. **Look up every sign.** `python3 tools/signbank.py <word>` lists every numbered entry with
   definitions, keywords and region. `--search` lists related keywords.
   Choose the entry whose definition matches the meaning you're teaching. Prefer `AustraliaWide`.
   If the meaning only exists as regional entries (region tags such as `SouthernDialect`, `NorthernDialect`,
   `WesternAustralia`, `Queensland`…), add **one** sign key with every matching entry in `variants`.
   Visitors then automatically see their own region's version.
   Keys are case-sensitive on Signbank (`J`, `Japan`); the tool tries other casings.
   **Never guess or construct video URLs.** Use only what the tool returns.
3. **Look at the signs before describing them.** Compile once:
   `swiftc -O tools/framesheet.swift -o tools/.bin/framesheet`, then
   `tools/.bin/framesheet <mp4 url> <scratchpad>/sheet.png 8 4` and Read the PNG.
   Write the Hand / Where / Move / Face notes from what the frames show. Where the stills are
   ambiguous, say "watch at 0.5×" rather than inventing detail. For signs with variants, describe each version.
4. **Add the signs** to `data/signs.json` (keep letters first, then vocab), with `lessons: [id]`.
   If a sign already exists, append the lesson id instead of duplicating it.
5. **Write the page.** Copy `lessons/_template.html` to `lessons/NNN-slug.html` and set `<title>`,
   `data-lesson`, the hero, goals, vocab cards, notes, phrases, mirror steps, quiz and recap.
   Use `<sign-phrase>` glosses in Auslan word order, with a `face` hint. Put Deaf-culture notes in `.note.culture`.
6. **Register it.** Append to `data/lessons.json` and tick it off in `curriculum.md`.
7. **Trim.** Run `python3 tools/trim.py` (macOS only). It finds where the signing happens in each new clip, so phrases
   and fingerspelling play smoothly. Cloud sessions can't run it; untrimmed signs still play, just with pauses.
8. **Verify.** Run `python3 tools/phrases.py` (collects lesson phrases for the Review phrase game), then `python3 tools/stamp.py` (cache-busts `assets/app.js` and `app.css` in every page, including new
   ones, and updates meta descriptions + `sitemap.xml` from `data/lessons.json`), then `python3 tools/check.py --online`; it must print OK. Any edit to `assets/` also needs `stamp.py`,
   or browsers keep serving the old cached copy.
9. **Publish.** Commit and push. Then reply with the lesson title, the live URL
   (https://auslan-tutor.com.au/lessons/NNN-slug.html) and a one-line summary.

## Cloud sessions (Claude Code on the web / phone)
Cloud sessions run on Linux with a fresh clone of GitHub, so:
- `CLAUDE.local.md` isn't there. Don't assume the author's region or progress.
- `tools/framesheet.swift` needs macOS and won't run. Describe new signs from the Signbank definition and keywords
  only, keep the Hand / Where / Move notes short and cautious, and add "Watch at 0.5×". Say in the PR that frames
  weren't checked, so the author can re-check them on the Mac.
- Signbank lookups and `check.py --online` need network access to `auslan.org.au` and `object-store.rc.nectar.org.au`.
  If they're blocked, say so in the PR rather than guessing URLs.
- Work on a branch and open a pull request. Don't push to `main`; the author reviews and merges.

## Teaching conventions
- Glosses go in CAPITALS with hyphens for multi-word signs (THANK-YOU). Fingerspelling is written S-A-M.
- Always teach the facial expression or non-manual features along with the hands.
- Be honest about uncertainty, and point learners to the Signbank entry (each card links to it) or a Deaf teacher.
- Encourage real-world practice: Deaf community events and classes with Deaf teachers. This app is a supplement.
- Signbank content is CC BY-NC-ND 4.0. Keep it non-commercial, credit it (each card links to its entry, and the
  footer credits Signbank), and don't modify the videos. They're hotlinked: Signbank's pages block iframes,
  but the MP4s play fine.
